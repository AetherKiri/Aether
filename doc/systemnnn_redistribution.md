# SystemNNN redistribution gate — source-only licensing review

Reviewed 2026-11-17. This is a narrow factual engineering audit, **not legal advice or a legal compatibility determination**. No author was contacted, no issue was filed, and no license or permission was changed. Parent source-integration work continues under the requested workflow; that instruction and this document do not authorize distributing a combined source or binary work.

## Release decision: HOLD public combined binaries

**Do not publish a SystemNNN-enabled combined Aether binary, application package, archive, or public CI binary artifact until the release owner records a qualified legal decision and any required rights-holder authorization.** A build/test pass, source availability, a fork, attribution, or an artifact named “link test” is not that decision. This is a release-process gate based on unresolved declarations, not a blanket assertion about every possible distribution arrangement.

| Gate | Observed blocker / required evidence to close |
| --- | --- |
| G1: declared GPL versions | Emberfall-owned runtime source is expressly GPL-2.0-only; Aether declares GPL-3.0-or-later. No specific Emberfall combination exception, dual-license grant, or permission resolving that mismatch was located in the bounded local review below. Record a qualified decision for the actual linked distribution; if additional permission is required, obtain and retain explicit authorization covering the relevant material, holders, versions and distribution. Alternatively review a genuinely different release composition; do not assume disabling one feature or changing linkage solves G1. |
| G2: product FFmpeg | The product manifest selects Bink2 outside Emscripten, and its FFmpeg overlay explicitly enables GPL/version3 for that feature. Do not label this product dependency “LGPL” based on the base port field, upstream Emberfall notice, or focused test build. Retain actual configure/license output and decide compatibility with G1 for the release closure. |
| G3: LGPL/static linkage | Record actual OpenAL and FFmpeg builds, notices, corresponding source/patches and a usable, reviewed relinking compliance path for the shipped configuration. A notice-only package is not proof of fulfillment. See bounded requirements below. |
| G4: dissemination | Apply this gate to public CI uploads as well as tagged releases. The initial mobile workflow snapshot uploaded its package directory with `if: always()`; the subsequent [diagnostic-only workflow](<../.github/workflows/systemnnn-mobile.yml#L158-L173>) removes that package payload. A combined product Build run was canceled while release uploads were pending. These mitigations do not close G1 or retrospectively remove existing artifacts; a release owner must assess all publishing paths. The licensing audit itself did not run CI. |

## Exact declarations and local permission evidence

- **Aether:** [root license](<../LICENSE#L1-L6>) is the GNU GPL version 3 text. The project-specific [README declaration](<../README.md#L444-L453>) says GPL-3.0-or-later; the [combined-work statement](<../THIRD_PARTY_LICENSES.md#L83-L87>) also says GPL-3.0-or-later in the OnscripterYuri section. The plain GPL text alone is not the basis for inferring “or later.”
- **Emberfall:** [third-party notices](<../packages/SystemNNN-Emberfall/THIRD_PARTY_NOTICES.md#L3-L9>) state `Copyright © 2026 PorisRora` and explicitly say Emberfall-owned source, including the current runtime-owned source, is **GPL-2.0-only**. [README](<../packages/SystemNNN-Emberfall/README.md#L41-L43>) repeats GPL-2.0-only. Its [license](<../packages/SystemNNN-Emberfall/LICENSE#L1-L7>) contains GPL version 2 text. Third-party components retain separate licenses; this is not a claim that all bundled code is GPL-2.0-only.
- The GPL2 [“How to Apply” example](<../packages/SystemNNN-Emberfall/LICENSE#L282-L299>) contains generic “any later version” language, but it is an example with placeholder author/program text, not a project-specific change to the explicit GPL-2.0-only notice. Likewise [section 10](<../packages/SystemNNN-Emberfall/LICENSE#L250-L256>) describes asking for permission; it does not record permission already granted.
- The local commit [338a5a17](https://github.com/AetherKiri/SystemNNN-Emberfall/commit/338a5a17ae72b4051e5037641067b9c230178b02), authored by PorisRora, is titled “docs: license Emberfall under GPL-2.0-only.” Its diff introduces GPL2 license text and the explicit GPL-2.0-only README/notice statements. The earlier notice asked for a licensing determination before public distribution; its replacement is the specific GPL2-only declaration, not a GPL3 exception.
- **An additional permission exists, but not the one needed to establish Emberfall compatibility:** [COPYING.iOS](<../COPYING.iOS#L13-L51>) is a limited App Store permission by approving holders for material they can license, and expressly does not grant/alter third-party rights. Its [official-distribution restriction](<../COPYING.iOS#L72-L91>) also limits reliance. No Emberfall-holder approval resolving G1 was located. The [OnscripterYuri correspondence reference](<../THIRD_PARTY_LICENSES.md#L73-L87>) concerns that separate component, not Emberfall. Neither is evidence of a general third-party exception.
- The adapter is not merely an unrelated repository next to Aether: its [CMake target](<../bridge/systemnnn_runtime/CMakeLists.txt#L56-L68>) is STATIC and links `emberfall-scene`, OpenAL and FFmpeg. This establishes the build composition needing review; it is not a legal determination of derivative-work boundaries.

**Bounded negative result:** searched current Emberfall Markdown documentation for GPL/license/permission/exception/dual-license and Chinese permission/license terms, Aether documentation and root notices for corresponding statements, and locally available child `git log --all` license/README/notice history and licensing/permission commit subjects. Inspected the explicit licensing commit diff. Available child refs included the integration branch and origin main/integration refs. No fetch, external correspondence search, exhaustive all-history content scan, contributor-rights validation, or per-file provenance audit was performed. “Not located” is not a claim that no permission can exist elsewhere. At initial review the root third-party notice search had no SystemNNN/Emberfall entry; an attribution addition alone would not close G1.

## FFmpeg: three distinct configurations, not one license label

1. **Root product overlay:** [registry configuration](<../vcpkg-configuration.json#L3-L12>) selects local overlay ports. [Root manifest](<../vcpkg.json#L30-L42>) selects avcodec/avformat/swresample/swscale and `bink2` on `!emscripten`. The [overlay metadata](<../vcpkg/ports/ffmpeg/vcpkg.json#L1-L28>) is version 8.1.2, base LGPL-2.1-or-later, and explicitly describes Bink2 as GPL-3.0-or-later, turning the build into GPL version 3. The [recipe](<../vcpkg/ports/ffmpeg/portfile.cmake#L35-L46>) appends exactly `--enable-gpl --enable-version3 --enable-decoder=bink2` when selected; otherwise it appends `--disable-decoder=bink2`. The Bink2 patch is included in the source acquisition at [lines 1–9](<../vcpkg/ports/ffmpeg/portfile.cmake#L1-L9>). The [license-install logic](<../vcpkg/ports/ffmpeg/portfile.cmake#L642-L662>) chooses the COPYING file from configure’s `License:` output, including GPL3, LGPL2.1/3, GPL2, and nonfree cases. The base manifest field cannot override those flags. This is source configuration evidence, not certification of a particular final product binary.
2. **Focused native/mobile tests:** [native manifest](<../tests/systemnnn_native/vcpkg.json#L14-L19>) and [mobile manifest](<../tests/systemnnn_mobile/vcpkg.json#L16-L29>) disable FFmpeg default features and request just avcodec/avformat/swresample/swscale; neither requests Bink2 or GPL features. The observed local Android dependency installation reports **FFmpeg 9.0.2** in its [generated version header](<../build/systemnnn-mobile-android/vcpkg_installed/arm64-android/include/libavutil/ffversion.h#L1-L5>) and includes LGPL2.1 text in its [installed copyright](<../build/systemnnn-mobile-android/vcpkg_installed/arm64-android/share/ffmpeg/copyright#L1-L13>). Its [SPDX record](<../build/systemnnn-mobile-android/vcpkg_installed/arm64-android/share/ffmpeg/vcpkg.spdx.json#L1021-L1068>) reports port 9.0.2#1 and `NOASSERTION`, not an independent affirmative license conclusion. No actual FFmpeg configure log/config header was found inside this focused build directory. These facts do not establish that every focused or product build is LGPL. The [workflow](<../.github/workflows/systemnnn-mobile.yml#L127-L134>) uses the focused manifest and focused triplets; it is not the root product build.
3. **Upstream Emberfall Android:** its [notice](<../packages/SystemNNN-Emberfall/THIRD_PARTY_NOTICES.md#L20-L22>) declares FFmpeg 8.1.3 LGPL2.1-or-later, five dynamic libraries for default/split packaging and static linkage for single-library packaging. Its [codec script](<../packages/SystemNNN-Emberfall/platform/android/build_movie_codec.sh#L46-L59>) enables a narrow demuxer/decoder set and does not enable GPL/version3. That declaration/script is not evidence of Aether’s product FFmpeg configuration.

For each actual release, retain source revision/archive digest, all applied patches, vcpkg baseline and port, features/triplet, configure command, `License:` output, installed notices, exact linked dependency inventory, and a corresponding-source/rebuild delivery plan. If LGPL is the approved path, review its selected-version obligations; if GPL3 is selected, review GPL obligations and the G1 mismatch. No unsupported claim that Bink2 removal alone authorizes release is made.

## OpenAL Soft: bounded static relinking checklist

The [product overlay](<../vcpkg/ports/openal-soft/vcpkg.json#L1-L8>) declares OpenAL Soft 1.25.1 LGPL-2.0-or-later. The [port recipe](<../vcpkg/ports/openal-soft/portfile.cmake#L22-L26>) chooses SHARED or STATIC from `VCPKG_LIBRARY_LINKAGE` and [installs COPYING and pffft notice](<../vcpkg/ports/openal-soft/portfile.cmake#L114-L117>). Android/iOS product triplets choose static libraries: [Android](<../vcpkg/triplets/arm64-android.cmake#L1-L9>), [Android dynamic exceptions](<../vcpkg/triplets/android-dynamic-libs.cmake#L1-L5>) (SDL2 only), [iOS](<../vcpkg/triplets/arm64-ios.cmake#L1-L4>). The focused triplets inherit those settings ([Android](<../tests/systemnnn_mobile/triplets/arm64-android.cmake>), [iOS](<../tests/systemnnn_mobile/triplets/arm64-ios.cmake>)); the local focused Android [imported target](<../build/systemnnn-mobile-android/vcpkg_installed/arm64-android/share/openal-soft/OpenALTargets.cmake#L57-L64>) is explicitly STATIC. Linux’s [product triplet](<../vcpkg/triplets/x64-linux.cmake#L1-L5>) instead selects dynamic libraries; do not generalize one platform to all.

For an LGPL2 section-6 distribution path, the installed [Library GPL text](<../build/systemnnn-mobile-android/vcpkg_installed/arm64-android/share/openal-soft/copyright#L260-L309>) requires terms permitting own-use modification and reverse engineering for debugging, prominent library-use/license notice and the license copy, and one of its specified material-delivery alternatives. Section 6(a) identifies corresponding library source including changes and complete machine-readable application object code **and/or source code** enabling modification of the library and relinking. Sections 6(b)–(d) state alternative delivery arrangements. Do not overstate this as requiring object files in every case; verify a usable selected route rather than merely pointing at a repository. [Section 4](<../build/systemnnn-mobile-android/vcpkg_installed/arm64-android/share/openal-soft/copyright#L216-L227>) addresses library object/source delivery. [Section 3](<../build/systemnnn-mobile-android/vcpkg_installed/arm64-android/share/openal-soft/copyright#L200-L214>) contains a GPL conversion option; this audit does not exercise it or change any notices.

Release evidence should demonstrate recipients can rebuild/relink the actual application with a modified OpenAL using provided source and/or linkable objects, scripts, toolchain/dependency details and instructions under the approved compliance path. Review platform signing/installation and store terms separately; an internal successful static link or Aether’s limited App Store permission is not proof of a recipient-usable compliance path. Preserve pffft/other included notices too. These points are a bounded checklist grounded in the observed text, not a complete dependency/store-law audit.
