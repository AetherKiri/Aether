# SystemNNN / Emberfall runtime

SystemNNN is an independent native Aether runtime provider with ID `systemnnn`. It owns Emberfall `GameSession` instances, the story compositor, a portable presenter and FreeType text renderer, OpenAL audio output, FFmpeg movie playback, startup sequencing, and persistence. Godot consumes complete CPU RGBA8888 frames through the shared `AetherRuntimePlayer`; this path does not require the KiriKiri VM, a separate SDL window, or an engine-owned GPU context.

## Source, branches, and license

Aether pins the `aether` branch of [AetherSystemNNN](https://github.com/AetherKiri/AetherSystemNNN/tree/aether) as a [submodule](../.gitmodules). The fork derives from [PorisRora/SystemNNN-Emberfall](https://github.com/PorisRora/SystemNNN-Emberfall).

The original author authorized licensing the Emberfall-owned code on this branch under GPL-3.0-or-later. The [license](../packages/AetherSystemNNN/LICENSE) and [third-party notices](../packages/AetherSystemNNN/THIRD_PARTY_NOTICES.md) are published with the fork. Aether builds FFmpeg with the features in its own vcpkg manifest, including Bink 2 on native platforms. The Android FFmpeg configuration described in the upstream notices applies to Emberfall’s standalone Android build.

## Build and registration

[The adapter build](../bridge/systemnnn_runtime/CMakeLists.txt) creates `aether_systemnnn_runtime` and links `emberfall-scene` plus the renderer/core dependency closure. It uses C++17, system PNG/zlib, FreeType, Iconv, nlohmann-json, Threads, OpenAL, and FFmpeg avformat/avcodec/avutil/swscale/swresample. FFmpeg is found through the package configuration or pkg-config. OpenAL is the chosen output backend; SDL3 is not this adapter’s audio backend.

`AETHERKIRI_SYSTEMNNN_DIR` defaults to `packages/AetherSystemNNN`. `AETHERKIRI_ENABLE_SYSTEMNNN` follows `AETHERKIRI_RUNTIMES_DEFAULT` on native platforms and defaults OFF for Web/Emscripten. Explicit cache options take precedence, but the bridge rejects a Web build when enabled. The root adds the bridge when the runtime is enabled and the extension or tests are requested. The extension links the adapter, defines `AETHERKIRI_WITH_SYSTEMNNN=1`, and calls `aether_systemnnn_register_runtime()` during scene initialization.

Build through the standard platform scripts or the root CMake project. The [Build workflow](../.github/workflows/build.yml) exercises the native provider in pull request Debug builds. CI uploads the standard Release artifacts with `AETHERKIRI_ENABLE_SYSTEMNNN=OFF`. Native regressions run through the root CTest suite. The [root manifest](../vcpkg.json) provides the shared dependencies.

For iOS, `AETHERKIRI_SYSTEMNNN_STATIC_TARGETS` lists the adapter and Emberfall static archives. The extension merge includes these archives and an archive-change dependency to force rebuilding the merged result. Imported dependencies still need the existing dependency sweep and final application linkage. An archive merge does not prove a working iOS export or device run.

## Session, frame, and input contract

[The provider](../bridge/systemnnn_runtime/src/systemnnn_runtime_provider.cpp) uses a per-instance game mutex to serialize session operations, decorative previews, movie decoding, text/presentation work and audio pulls. The audio worker acquires that mutex before pulling from the current session, so ownership replacement is serialized. Stopping or restarting that worker must happen outside the mutex because stop joins the worker. C ABI guards translate exceptions to error results and expose diagnostic text.

The presenter produces a transparent, premultiplied UI plane at the configured game resolution. The story path passes its matching plane key through `StoryCompositor` and its mailbox; advance is gated by the presented key and `request_advance()`, and pending short DRAW presentation suppresses further stepping. The provider publishes an immutable, tightly packed, top-down RGBA8888 snapshot with opaque alpha and increasing serial. Frame description retains the corresponding snapshot for the subsequent read even if a tick publishes a newer frame. The current acknowledgement boundary is successful provider CPU publication; physical display timing remains a separate host concern.

Library detection recognizes exactly `spt/sys.spt`, case insensitive in both components. Arbitrary SPT files and a root-level SYS.SPT do not select the runtime. Import detection works without the extension; the registered provider also probes directories. The launch entry remains the game directory, and the shell hides the executable selector. An explicitly supplied script entry is encoded for the game and starts directly in story mode.

Godot maps pointer positions and drag deltas to native frame pixels before sending them. The adapter does not scale those coordinates again by the requested presentation size. Right button 1 and Back/Escape route back/menu actions; Return/Space advances or chooses, number keys choose, Ctrl controls skip, and F5/F9 quick-save/load. Pause clears pending input and Ctrl skip, freezes ticks and audio/movie playback, and persists progress; resume resets frame pacing. These mappings do not establish full touch, gamepad or device-focus acceptance.

## Startup, UI, and text

[StartupSequence](../bridge/systemnnn_runtime/src/systemnnn_startup.cpp) follows configured logo, opening, printMovie and title stages, including configured colors, image canvases, timing, skips, decorative background sessions and title entrance. It does not step the main story while running a decorative preview. Startup movies and story `Wait::Movie` use the same portable movie player. A direct story entry bypasses this sequence.

[The presenter](../bridge/systemnnn_runtime/src/systemnnn_presenter.cpp) reads game configuration and artwork, then draws dialogue/name windows, choices, places, title/system controls, settings, backlog pages, slots and modal rows. Modal interactions preserve engine row IDs, enabled/locked/new/sold-out/purchase flags, pages/groups, chart coordinates and action codes. Name/kanji input requests an asynchronous host `runtime_form`; accepted UTF-8 fields are encoded back to game bytes with the modal byte limits. Cancellation returns through modal completion. [The native-panel routing policy](../bridge/systemnnn_runtime/src/systemnnn_native_panel.h) forwards move/down/up/cancel, Back and panel shortcuts, waits for the engine’s deferred menu request, and resumes the same session with script audio restarted when the host overlay closes. Saving checks the native panel’s save permission. These title-specific native modes 50/51/52 are separate from configured minigame types 1–10.

[TextRenderer](../bridge/systemnnn_runtime/src/systemnnn_text.h) uses FreeType memory faces so Unicode native font paths work on Windows. Before open, the shell stages the bundled CJK FontFile bytes from Godot resources into a readable native path and passes `systemnnn.font`; `default_font` and `font_dir` are also supported. Missing readable fonts fail open. Linux system font fallbacks are convenience paths, not the deployment font strategy.

Game text is strict CP932 with optional canonical58 SJIS tunnel, explicit legacy59 configuration decoding, and UIF substitutions. A valid UTF-8 BOM selects UTF-8; unmarked game text is not guessed as UTF-8. Reverse encoding rejects ambiguous/unrepresentable input and byte-limit overflow. The session filename encoder uses this codec for Unicode paths. The presenter adds fixed-cell dialogue placement and configured ruby/emphasis anchors over FreeType glyphs; the low-level plain-text helper strips valid annotations for contexts that need only body text. Ruby spanning a wrapped line is omitted with a diagnostic.

[The portable minigame board/frontend](../bridge/systemnnn_runtime/src/systemnnn_minigame.h) now implements all ten configured types: Puzzle, Change, Paint, Cross, Slide, Monte, Pyramid, Golf, Nikaku and Kushi. [The binding](../bridge/systemnnn_runtime/src/systemnnn_minigame_binding.cpp) exposes enabled title/Omake entries, checks caller mode and configured variables, loads instruction/board/card/tile artwork, forwards pointer and animation timing, plays configured system sounds and restores caller music on exit. Gallery images are selected from actual unlock keys with difference/system filtering; absent optional art uses fallback visuals. Only a one-shot frontend clear event calls `GameSession::complete_minigame(index)` and persists its configured reward. Paint intentionally has no clear condition and must not grant a synthetic completion reward. Board trace parity and binding fixtures are bounded evidence; final graphical and commercial-game minigame acceptance remain separate.

## Audio and movies

[AudioOutput](../bridge/systemnnn_runtime/src/systemnnn_audio.cpp) pulls interleaved stereo PCM16 at the session rate (currently 44.1 kHz) from Emberfall `GameAudio`, or the active movie. It owns its OpenAL device, context, queued buffers and worker lifecycle. `ALC_EXT_thread_local_context` is required so the worker does not disturb the host’s process-wide OpenAL context. Missing device/extension support produces an audio error and warning; successful silent continuation is not an audio acceptance result. Null-driver tests prove lifecycle behavior, not audible BGM, effects or voice.

[MoviePlayer](../bridge/systemnnn_runtime/src/systemnnn_movie.cpp) decodes local files through FFmpeg, produces CPU video frames and stereo PCM16, and uses tick-driven PTS playback with bounded decode work. Playback still completes without an audio sink; pause freezes the clock and sample consumption. Movie-list resolution uses one-based entries and raw CP932/case-aware paths under the game movie directory. Completion/skip resumes startup or story; unavailable or interrupted movies are logged and the provider resumes the corresponding continuation. Supported formats depend on the linked FFmpeg build. Generated MPEG4/AAC and FFV1/PCM fixtures do not prove commercial WMV/VC1/WMA playback or full product A/V synchronization.

## Slots and global progress

Normal shell launches supply per-installation writable roots at `user://systemnnn_games/<SHA256(normalized game root)>`, with a separate sibling cache. Slot files live below the writable root in `systemnnn/slot-N.sav` and the save export/import bank uses the same directory. Slot 0 is quick-save; numbered slots use the PC save codec. The provider-only fallback uses the game’s sav directory when no writable path is supplied. Moving an installation changes a path-derived identity and still needs migration acceptance.

Slots are exported with `export_presented_pc_save()`. Writes stage complete bytes before replacement, using Windows replacement semantics or POSIX flush/rename. Loads construct a candidate session with a forked runtime and replace the active owner only after successful validation. The provider inspects slots to populate occupancy, summaries, timestamps and thumbnails; synthetic provider checks cover this path, while final graphical inspection remains separate. Save/load failure behavior has independent synthetic fixture coverage, not a blanket crash-durability guarantee.

[Global progress persistence](../bridge/systemnnn_runtime/src/systemnnn_progress.cpp) handles versioned PC system archives, result and chart progress, Emberfall read/gallery sidecars and extension generations. It loads existing original sav data when private copies are absent, preserves malformed files and reports warnings, then syncs runtime names and parameters. The provider consumes engine system-save requests as well as persisting on slot save, pause, return to title, reopen and teardown. With a supplied writable root these progress writes target private storage. That does not guarantee the entire game directory is read-only: Emberfall layout inference can create its configuration cache under init/init2.

Persistence limits are explicit: older PC archives without SYSTEMFLAG2 cannot represent some settings/theme fields; legacy textual read identities are preserved but cannot be resolved by the native runtime; an unbound raw message cursor can be retained on disk but lacks a direct runtime restore setter. Cross-process save locking, all legacy save extensions and moved-installation recovery remain separate verification work.

## Remaining acceptance limits

The portable presenter does not yet establish Android/PC UI parity. Its source explicitly reports static normal/disabled button art without hover/press animation, button sounds, animated cursors or portrait lip animation. Backlog currently offers text paging; voice replay/jump parity is unverified. The presenter now uses native visible-text timing and a shared decoded-body glyph budget, including APPEND and ruby clipping. First-click reveal, frame acknowledgement, Auto synchronization and script wait timing pass the current authored ABI regressions; original per-glyph effect transitions and ruby wrapping across lines remain unverified. Some modal pages use portable generic rows and gallery previews are cropped. The configured minigame frontend is implemented for types 1–10, with bounded board/binding tests rather than full product acceptance. Core CardSystem mode 45 is separately unavailable in this Emberfall revision, including its Android player: it declines entry and exposes no gameplay/completion contract. Chart LeaveReady currently commits immediately rather than proving the original exit animation. Unknown overlays display a dedicated-frontend notice.

The actual Linux production extension has passed a local graphical authored-fixture run, but no Aether commercial-game route, mobile runtime, clean-machine redistributable package, complete opcode/effect coverage, every modal/minigame, or unrestricted extension-script compatibility is claimed here. Real audio devices, focus/background transitions, production movie codecs, final desktop dependencies, Android/iOS exports and device execution remain acceptance gates.
